# Security and governance

AI systems inherit ordinary application risks and add risks around untrusted prompts, retrieved documents, model outputs, training data, and tools. Controls belong in identity systems, application code, data access, infrastructure, and operations.

## Chapters

- [AI threat modeling and governance](ai-governance/README.md): assets, trust boundaries, prompt injection, data exposure, tool abuse, supply chain, and response.
- [Backend identity and LLM security](backend-security/README.md): authentication, authorization, tenant isolation, API threats, and LLM application controls.

Use [evaluation and MLOps](../11-evaluation-and-mlops/README.md) to test security behavior continuously. A model instruction is not an access-control boundary.
