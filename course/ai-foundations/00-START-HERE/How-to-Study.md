# How to study

## Daily rhythm

Use four blocks: recall prior ideas for 20 minutes; learn one concept for 75–90 minutes; work a small example for 45–60 minutes; implement/debug for about 90 minutes; then test, explain and log for 30–45 minutes. Take breaks. On day six, revise and integrate. Keep day seven free.

## Chapter loop

1. Check prerequisites and learning outcomes.
2. Explain the concept in plain language before code.
3. Trace data flow and annotate shapes/symbols.
4. Solve a small numeric example manually where possible.
5. Implement the smallest useful version.
6. Compare it with a maintained library or framework.
7. Test success, boundary and failure behavior.
8. Answer questions without notes.
9. State when the method should not be used.
10. Record evidence, mistakes and next steps.

## Codex as a tutor

Attempt the task before asking for generated code. Ask for a hint, critique, edge case, or explanation; verify it against official docs and a test. For unfamiliar generated code, annotate each line and change a requirement yourself. Never provide credentials, private customer data, or sensitive documents to a coding assistant.

Keep a mistake log: incorrect assumption, evidence that exposed it, corrected explanation, and a new test. Use spaced retrieval next day, end of week, end of month, and at each 8–12 week project review.

Reading gives exposure. Working knowledge means routine implementation plus known failure modes. Strong knowledge means selecting alternatives, testing and debugging under production constraints. Mastery for this path means you can design, implement, measure, explain and maintain the system.
